# Clean-destination archive acceptance

This check exercises the deployed web export UI and the shipped web import UI in a fresh, disposable local installation. It complements the earlier same-account roundtrip in [hosted browser archive verification](hosted-browser-archive.md). It is not a claim that another product implements Porchday’s format, or that the private repository has been publicly released.

`scripts/hosted-archive-migration.ts --run --attempt=<eight lowercase hex characters>` requires the existing private synthetic staging fixture. It operates only on synthetic A. Synthetic B’s pending recovery case and deleted synthetic C remain untouched. Every run writes an exclusive, owner-only intent before effects; a failed attempt must be inspected before a new attempt. The optional `--local-only` rehearsal performs no staging requests.

The destination helper creates a uniquely named database in the existing local PostgreSQL container, migrates it, and creates separate login roles inheriting the normal least-privilege runtime roles. It does not alter shared role passwords or insert users, verified identities, sessions, member keys, or imported records directly. An ordinary local development invitation is the only fixture DML. The full API runs in workerd with local native R2 and an initialized independent privacy journal. The email binding captures the normal verification message in process memory; the browser follows its exact local verification link. No real email is sent and no token is read from SQL.

The fresh account signs up, verifies its address, logs in, and creates encryption keys in the real browser UI. Its identity and key fingerprint must differ from A. The source browser uses A’s existing saved device and normal recovery-secret unlock. It cannot submit profile, device, relationship, or import mutations. A separate bounded member API step creates one fresh private post, its JPEG, and an independently expiring comment, with IDs recorded before their first request.

The source UI downloads its default protected archive. The separate archive secret stays in memory. The maintained OpenPGP and archive parser verify the parts, original JPEG checksums, source account, and the new fixture. The harness refuses archives above four parts, 40 authored entries, or 16 photos; this is a test fixture bound, not a product limit. It waits for the original comment’s absolute deadline before previewing and importing the unchanged archive in the new installation.

The destination explicitly replaces its newly initialized profile with the archived profile. A browser request guard admits only fresh, captured private import IDs, exact source timestamps/deadlines, the destination’s devices, and the next revision of the destination’s own profile. It blocks source-account profile replacement, unknown writes, extra recipients, extended deadlines, and expired source entries before submission. Successful verification requires exact coverage of all eligible authored entries and eligible orphan-photo journals, not merely one surviving example.

Independent decryption checks the imported text, original provenance and timestamps, profile fields, JPEG bytes, and distinct post/photo expiration deadlines. The old source private key must fail to decrypt the new content. The browser must decode the imported photo. Connections, connection requests, group memberships and invitations must remain empty. Comments and reactions retain the documented private-journal representation; the import does not reconstruct old conversations or relationships.

Cleanup uses the real source post/media deletion endpoints and the destination account deletion endpoint. It verifies source profile/device checksums, immediate source API denial, destination auth-identity absence and saved-session denial, and clears browser keys/cookies. The local browser, database, unique runtime roles and local R2 storage are removed only after their processes close. Physical source R2 removal is a separate observation after the normal delayed second pass; source API denial alone is not described as physical erasure, and existing seven-day backup retention still applies.

Evidence receipts and protected downloads remain under ignored `artifacts/private/hosted-smoke` with owner-only permissions. No plaintext archive, archive key, destination recovery secret, verification token, browser trace, or screenshot is written into the repository or printed in diagnostic output. Failed attempts preserve fixed phase/status evidence without publishing private errors.
