# Encrypted web videos and calendar day navigation

The web composer accepts MP4, MOV and WebM clips up to 10 MiB and 4K pixel area, subject to the browser's decoder. It checks container signatures and actual browser decoding before encryption. H.264 MP4 is the most broadly useful choice; no codec conversion or server transcoding is performed. Video metadata, including metadata in the original file, is encrypted and shared with the selected audience. The composer discloses this; unlike normalized photos, original video metadata is not stripped.

Videos use the existing signed/encrypted media envelope and authenticated upload/download endpoints. No database migration or expanded audience is needed. The 22,020,096-byte server envelope limit and member quota remain in force. Oversize encrypted composer attachments fail before reservation. A small JPEG preview is inside the encrypted post; its deadline is retained when re-sharing or importing. Full videos download only after Load video, never just because the feed/calendar scrolls past them. Object URLs are released when media expires or the component unmounts. Playback does not autoplay.

The web calendar can feature video previews. Earlier months append automatically while scrolling down, with a Load earlier month fallback. Filters apply across all loaded months. Each month retains its own pagination and error/retry state; months outside the viewport do not repeatedly fetch/decrypt on focus. Appending older months preserves existing month identities and scroll position. Left swipe in the day detail advances a day; right swipe goes back. Calendar arithmetic crosses month/year/daylight-saving boundaries. Vertical gestures, long drags and gestures starting on interactive controls do not change days. Previous day and Next day buttons provide a keyboard-accessible alternative. Crossing months requests the newly selected month and preserves filters.

Web export/import, re-sharing and full-history sharing validate supported video bytes and preserve the existing audience/deadline rules. Archive media retains the version-1 manifest shape, with MIME-matched .mp4/.mov/.webm paths. Older photo-only importers reject these rather than treating video as a JPEG. Profile pictures and custom emoji remain photo-only.

Compatibility limits: older web bundles and the currently photo-only native client do not play video attachments or import video-containing archives; post text remains in the existing format. A web release does not distribute a native binary. Installed service-worker, real iPhone MOV/HEVC and native-device behavior need separate verification. Browser support is checked on the sender and receiver; unsupported playback produces a visible error. Larger videos require separately reviewed chunked encryption/upload, bounded decoding and resumable transfer work, not merely increasing the current JSON envelope cap.

Validation is tracked in issue #108. The calendar browser check uses real Chromium, a generated synthetic WebM, and synthetic API/vault transport. It verifies selection, validation, byte retention, click-to-load playback and day navigation; it is not hosted cryptographic or device acceptance.
